## Player

`shared_script '@n_bridge/init.lua'` then `Bridge.GetPlayer(source)`, or `exports.n_bridge:GetPlayer(source)`.

Cash is the default account. `AddPlayerMoney(source, 500)` adds cash.

### GetPlayer

```lua
local player = Bridge.GetPlayer(source)
```

**Parameters**

- `source` `number`

**Returns**

- `nil`, or a player table:

```lua
{
    source = 12,
    identifier = 'citizenid, license, or character id',
    name = 'Jane Doe',
    job = { name = 'police', grade = 2, label = 'Police', gradeLabel = 'Officer', onDuty = true },
    gang = { name = 'none', grade = 0, label = 'none', gradeLabel = 'none', onDuty = false },
}
```

### GetPlayers

```lua
local sources = Bridge.GetPlayers()
```

**Returns**

- `number[]` server ids

### GetIdentifier

```lua
local id = Bridge.GetIdentifier(source)
```

**Returns**

- `string` or `nil`

### GetPlayerJob

```lua
local job = Bridge.GetPlayerJob(source)
```

**Returns**

- job table (`name`, `grade`, `label`, `gradeLabel`, `onDuty`)

### GetPlayerGang

Same shape as the job. `name` is `none` when the framework has no gang.

### GetPlayerMoney

```lua
Bridge.GetPlayerMoney(source, 'bank')
```

**Parameters**

- `source` `number`
- `account` (optional) `string` — `cash` (default) or `bank`

**Returns**

- `number`

ESX maps `cash` to the `money` account. ox_core `cash` is the `money` item. ox_core `bank` is the character account.

### AddPlayerMoney

```lua
Bridge.AddPlayerMoney(source, 'cash', 250)
```

**Returns**

- `boolean`

### RemovePlayerMoney

```lua
Bridge.RemovePlayerMoney(source, 'bank', 100)
```

**Returns**

- `boolean` — `false` when the balance is too low or the player is missing

### HasPermission

```lua
Bridge.HasPermission(source, 'admin')
```

**Returns**

- `boolean`

`standalone` checks ACE only.

### OnPlayerReady

```lua
Bridge.OnPlayerReady(function(source)
end)
```

**Parameters**

- `handler` `function` — receives the server id

**Returns**

- `boolean`

Players who loaded before the handler was registered are still passed in. This is an export.

## Notify

```lua
Bridge.Notify(source, {
    title = 'Garage',
    description = 'Vehicle stored',
    kind = 'success',
    duration = 4000,
})
```

**Parameters**

- `source` `number`
- `data` `table` — `title`, `description`, `kind` (`info`, `success`, `warning`, `error`), `duration` milliseconds

**Returns**

- `boolean`

The client notify provider draws it. Server code does not call ESX or QB notify itself.

## Keys

```lua
Bridge.GiveKeys(source, plate)
Bridge.RemoveKeys(source, plate)
```

**Returns**

- `true` or `false`

qs-vehiclekeys uses an optional model string: `GiveKeys(source, plate, 'ADDER')`. qbx_vehiclekeys and p_vehiclekeys need that plate spawned.

## Phone

```lua
Bridge.SendPhoneMail(source, {
    sender = 'City Hall',
    subject = 'Licence',
    message = 'Approved.',
    address = 'jane@mail.com',
})

Bridge.SendPhoneNotification(source, {
    title = 'City Hall',
    description = 'Approved.',
    app = 'Mail',
})
```

**Returns**

- `true` or `false`

lb-phone looks up the equipped phone email when `address` is omitted. sky_phone mail returns `false`.

## Dispatch

```lua
Bridge.SendDispatch({
    source = source,
    code = '10-31',
    title = 'Store robbery',
    message = 'A clerk triggered the alarm.',
    jobs = { 'police' },
    priority = 'high',
    blip = { sprite = 161, color = 1, scale = 1.0, length = 5 },
})
```

**Parameters**

- `data.source` `number` — required for cd_dispatch, cd_dispatch3d, and ps-dispatch
- `data.code` `string`
- `data.title` `string`
- `data.message` `string`
- `data.jobs` `string` or `string[]`
- `data.coords` `vector3` — falls back to that player's ped
- `data.priority` `string` or `number`
- `data.blip` `table` — `sprite`, `color`, `scale`, `length`

**Returns**

- `true` or `false`
