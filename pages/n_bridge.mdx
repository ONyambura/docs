# N Bridge

One function, whichever framework or inventory the server runs. Your resources call `Bridge` and stop branching on ESX, QB, Qbox, ox_core, vRP, and inventory scripts.

<Callout type="warning">
Start the framework and the inventory before `n_bridge`. Start every NXBR resource after it.
</Callout>

### Start order

```bash
ensure oxmysql
ensure qbx_core
ensure ox_inventory
ensure ox_lib
ensure n_bridge
```

Swap in `es_extended`, `qb-core`, or `qb-inventory` when that is what the server runs.

### Pick backends in config.lua

`auto` uses the first started resource in `core/catalog.lua`. Set an id to force one.

```lua
Config.Use = {
    framework = 'auto', -- esx | qb | qbox | ox | nd | vrp | standalone | custom
    inventory = 'auto',
    notify = 'auto',
    target = 'auto',
    progress = 'auto',
    appearance = 'auto',
    fuel = 'auto',
    keys = 'auto',
    phone = 'auto',
    dispatch = 'auto',
    society = 'auto',
    vehicles = 'auto',
    textui = 'auto',
    bossmenu = 'auto',
}
```

The server console prints the choice on start: `framework=esx inventory=ox notify=ox_lib ...`.
</Steps>

## Readable files

Keymaster escrow leaves these plain. Everything else under `providers/` is locked:

- `fxmanifest.lua`, `config.lua`, `init.lua`
- `core/**` (routing only, no third-party calls)
- `providers/**/custom/**`
- `docs/**`

## What 0.6.0 ships

Framework, inventory, notify, target, progress, appearance, fuel, keys, phone, dispatch, society, owned vehicles, text UI, and boss menu.

Each export page lists one function per section: parameters, the return value, and a full example. Player calls include job, gang, duty, metadata, and lookup by identifier. ND Core is a framework provider.

Client reads do not take a server id: inventory count, items, weapon, and open; keys give, remove, has, and lock; gang and identifier. n_carlock and wasabi_carlock are separate providers.
