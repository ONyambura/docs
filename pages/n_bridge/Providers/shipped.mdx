# Shipped backends

`auto` walks the open `core/catalog.lua` and keeps the first started resource. `qbx_core` is ahead of `qb-core`. Dedicated inventories are ahead of a resource named `inventory` and ahead of `es_extended`. Dedicated notify, progress, text UI, input, and menu resources are ahead of `ox_lib`, because most servers run ox_lib as well.

## Framework

- `qbox` — `qbx_core`
- `qb` — `qb-core`
- `esx` — `es_extended`. `cash` is the `money` account.
- `ox` — `ox_core`. Cash is the `money` item. Bank is the character account.
- `nd` — `ND_Core`. Cash and bank are character fields. There is no gang table and no set-money call.
- `vrp` — `vrp`. Classic proxy calls, plus vRP 2 `users_by_source` when present.
- `standalone` — no framework. `HasPermission` is ACE. Money stays `0`.
- `custom` — open template

## Appearance

`op-clothing` is first. It provides the other clothing resource names, so those look started while it is running.

- `op-clothing` — wardrobe by default. Pass a shop id to `OpenAppearance`.
- `illenium-appearance` — saved skin is `users.skin` on ESX, otherwise the active `playerskins` row. Outfits from `player_outfits`.
- `fivem-appearance` — reads `users.skin` or `playerskins`, and `player_outfits` in either column layout, when those tables exist.
- `rcore_clothing` — saved skin by identifier. Outfits from `rcore_clothing_outfits`.
- `qb-clothing` — saved skin from the active `playerskins` row. Outfits from `player_outfits`. The client reads the ped into qb-clothing's skin format.
- `esx_skin` — saved skin from `users.skin`. The client uses skinchanger. No outfit list.
- `custom`

## Keys

- `n_carlock` — server `GiveKeys(source, plate)`, client `GiveKeys(plate, target)`, `HasKey`, `ToggleLock`
- `wasabi_carlock` — server `GiveKey(source, plate)`, client `GiveKey(plate)`
- `qbx_vehiclekeys` — plate is resolved to a spawned vehicle entity
- `qb-vehiclekeys` — server `GiveKeys` / `RemoveKeys`
- `qs-vehiclekeys` — `GiveServerKeys` / `RemoveServerKeys`
- `Renewed-Vehiclekeys` — server `addKey` / `removeKey`
- `MrNewbVehicleKeys` — server `GiveKeysByPlate` / `RemoveKeysByPlate`
- `p_vehiclekeys` — client `createKey` / `removeKey`. The vehicle must be networked.
- `vehicles_keys` — jaksam's key script, by plate
- `mk_vehiclekeys` — by vehicle entity. The vehicle must be spawned.
- `t1ger_keys` — temporary keys only. Remove and has-keys return `false`.
- `F_RealCarKeysSystem` — sent through the player's client
- `mVehicle` — key items for a spawned vehicle
- `cd_garage` — sent through the player's client
- `okokGarage` — has-keys returns `false`
- `custom`

## Phone

`sky_phone` and `sd-phone` are ahead of `17mov_Phone`, `lb-phone` and `yseries`, because both provide those names.

- `sky_phone` — number, call, and open state through sky's own exports. Mail, messages, and disable return `false`.
- `17mov_Phone` — mail, messages, notifications, and calls. The disabled state is tracked by n_bridge.
- `sd-phone` — `notify`, `sendMail`, `sendSystemMessage`, and calls. Mail uses `data.address`, or `getMailAddresses` for the player identifier.
- `lb-phone` — notifications, mail, messages, and calls. Without an address, the equipped phone email is used.
- `yseries` — TeamsGG notifications, mail, messages, and calls by server id. No client notification.
- `gksphone` — mail, messages, notifications, and calls. The phone cannot be disabled.
- `okokPhone` — the phone cannot be opened or disabled from a script. Call checks ask the player's client.
- `qs-smartphone-pro` — no lookup from a number to a player, no call checks, and the phone cannot be opened from a script.
- `qs-smartphone` — no lookup from a number to a player. The client can only check whether the phone is open.
- `qb-phone` — mail, notifications, and ending calls. No texts, no call check, and no client open, close, or disable.
- `custom`

## Status

Health and armor use natives and work with any framework. The providers below cover needs such as hunger, thirst, and stress.

- `esx_status` — its `set`, `add`, and `remove` events. The server reads the live value from the player's client.
- `qbox` — `qbx_core` metadata and the player state bag
- `qb` — `qb-core` metadata. Hunger, thirst, and stress changes also refresh qb-hud.
- `ox` — `ox_core` statuses. Only statuses registered in ox_core exist.
- `custom`
