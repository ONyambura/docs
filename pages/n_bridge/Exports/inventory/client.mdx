# Client

Local inventory. These calls do not take a server id.

The names follow [ox_inventory client functions](https://overextended.dev/ox_inventory/Functions/Client). Other inventories implement count, items, label, weapon, and open when that script has the export.

```lua
Bridge.GetItemCount('water', metadata)
Bridge.HasItem('water', 1, metadata)
Bridge.GetItemLabel('water')
Bridge.GetSlotWithItem('water', metadata)
local items = Bridge.GetPlayerItems()
local weapon = Bridge.GetCurrentWeapon()
Bridge.GetPlayerWeight()
Bridge.GetPlayerMaxWeight()
```

Each row is `{ name, count, metadata, slot, label }`. `GetCurrentWeapon` returns one row, or `nil`. Weight calls are ox_inventory.

```lua
Bridge.OpenInventory('stash', { id = 'police_locker', owner = 'license:xxxxxxxx' })
Bridge.OpenInventory('player', target)
Bridge.OpenInventory('shop', { type = 'General', id = 4 })
Bridge.OpenInventory('trunk', { netid = NetworkGetNetworkIdFromEntity(vehicle) })
Bridge.CloseInventory()
Bridge.SetStashTarget('motel5', 'bobsmith')
```

ox_inventory `OpenInventory` kinds include `player`, `shop`, `stash`, `crafting`, `container`, `drop`, `glovebox`, `trunk`, and `dumpster`. ESX and chezza return `false`. jaksam returns `false` for another player.

```lua
Bridge.UseSlot(1)
Bridge.GiveItemToTarget(serverId, slot, count)
Bridge.DisplayMetadata({ serial = 'Serial' })
```

`UseSlot`, `GiveItemToTarget`, `DisplayMetadata`, and `SetStashTarget` are ox_inventory. Adding and removing items stays on the server.
